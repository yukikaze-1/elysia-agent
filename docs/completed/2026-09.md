### 7.4 这一轮反复出现的四类形状

修到后半程可以归纳出**缺陷的家族**——比单项更有价值，也是下一轮 review 的检查表：

1. **「声明了但到不了」**：`MISSING_DEPENDENCY` 有 fatal 分类但产生它的分支恒不可达；
   `WorkflowState.error` 有字段有消费方但**零生产者**；空图对"全部 required 成功"
   空真；`self_perception_history` 有读取方、有上限常量、**没有写入者**。
   —— 读代码时每一处看起来都对。
2. **「两条路径不对称」**：v2 有闸门 v1 没有；`/ready` fail-closed 而历史接口 fail-open；
   四条删除路径三条记 tombstone 一条不记；同一份 services 里一个字段实时一个不实时。
3. **「失败语义静默」**：只 `logger.debug` 的降级、`_db is None → return 0`、
   `retryable` 的拒绝被落成终态、无条件复位计数器。
4. **「测试前提不真实 / 没走到被测路径」**：fixture 用固定过去时间戳、假库不建目录、
   用默认 `read_dirs` 却把文件建在 `tmp_path`、键不一致在单测中不可见。
   ——**每一次「反证全绿」都是这一类的现场**。
