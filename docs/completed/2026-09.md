### 7.4 这一轮反复出现的四类形状

修到后半程可以归纳出**缺陷的家族**——比单项更有价值，也是下一轮 review 的检查表：

1. **「声明了但到不了」**：`MISSING_DEPENDENCY` 有 fatal 分类但产生它的分支恒不可达；
   `WorkflowState.error` 有字段有消费方但**零生产者**；空图对"全部 required 成功"
   空真；`self_perception_history` 有读取方、有上限常量、**没有写入者**。
   —— 读代码时每一处看起来都对。
2. **「两条路径不对称」**：v2 有闸门 v1 没有；`/ready` fail-closed 而历史接口 fail-open；
   四条删除路径三条记 tombstone 一条不记；同一份 services 里一个字段实时一个不实时。
3. **「失败语义静默」**：只 `logger.debug` 的降级、`_db is None → return 0`、
   `retryable` 的拒绝被落成终态、无条件复位计数器。
4. **「测试前提不真实 / 没走到被测路径」**：fixture 用固定过去时间戳、假库不建目录、
   用默认 `read_dirs` 却把文件建在 `tmp_path`、键不一致在单测中不可见。
   ——**每一次「反证全绿」都是这一类的现场**。

## 九、CI 全历史 secret scanning 假绿修复（09-14，1 个提交）

owner 反馈 CI 两个 job 同一条用例红：`test_end_to_end_catches_the_real_historical_leak`

`test_shallow_checkout_refuses_to_report_green` / `test_real_repo_full_history_verdict_is_faithful`）
断言"全历史必须命中 2026-06 那次泄露"，实得"✓ 通过"。

**先定性**：那次 CI 跑的是 `334e3a8`（第八节 10 个提交**尚未推送**——本机无 push
凭据）。证据是 runner 工作区 `.git/FETCH_HEAD` 与两个 job 的 Worker 日志（日志里
**没有** `check-timeouts`/`check-contract` 步骤，那是第八节才加的）。所以这是
`67eeab83` 带进来的**既有红灯**，不是 A 组六项造成的；但推上去会照样红。

**根因**：CI 的 checkout 是 `--depth 1`（self-hosted 显式 `git fetch --depth 1`，
GitHub-hosted 的 `actions/checkout@v4` 默认亦然）。浅克隆里 `rev-list --all` 只覆盖
**最后一个提交**，于是：

- 测试的断言（"老提交里必须命中"）**不可能成立**；
- 更糟的是脚本本身报**假绿**——`--all-refs` 打印"✓ 无凭据形态命中"并退出 0，
  而它其实只扫了一个提交。"没扫到"与"干净"被混为一谈。
- 那用例还把"预期为红"写死：owner 清完历史后必然转绿 → **一条会在 owner 做对事情时
  炸的测试**。

**修复（三层，见 `CODE_REVIEW_REPORT.md` §0.4.9）**：

1. 脚本**拒答**：`--all-refs` 检测到浅克隆 → "✗ 无法判定" + **退出码 2**，绝不打印通过标记；
2. 新增**合成仓库**端到端（提交 1 抄凭据 / 提交 2 删文件 → 工作树绿、全历史红），
   证据不再依赖本仓历史，CI 与本地同结论；
3. 真实仓库那条**期望值现算**（`git log -S` pickaxe）+ 浅克隆显式 skip（原因写进 skip）。

**验收**：浅克隆复现 owner 报错逐字一致（`assert 0 == 1` + "✓ …通过"）；同一浅克隆
打修复后 **31 passed, 1 skipped**；完整 clone **32 passed**；注入复现两处（去掉拒答 →
`assert 0 == 2`；历史模式返回 0 个对象 → `assert 0 == 1`）。
