## 4. Finding-by-Finding Evidence

### B3-CB-1 — `pronouns = null` write-valid / read-invalid → **FIXED**

**入口**：`PUT /api/me`（REST，本地单用户，无需 admin）。

**setup / action / expected / actual**

```text
Setup:    权威 store（UserIdentityRepository + 真实 MongoDB 8，探针库）
Action:   PUT /api/me {"displayName":"妖梦","pronouns":null,
                       "locale":"zh-CN","timezone":"Asia/Shanghai","expectedRevision":1}
Expected: 200 + pronouns=null（读契约本就是 string|null）
Actual:   500 INTERNAL —— 而 Mongo **已提交** pronouns=null / revision 1→2 / initialized=true
          重启后 connect() → None，GET /api/me → 503 STORAGE_UNAVAILABLE（永久）
```

**原报告 vs 实测**：原记录写「持久化成功 → 后续读取 500」。实测**更重**：

1. **PUT 自己就 500**（读回发生在 `repo.update_if_revision` 内，见下方 traceback）；
2. 同进程 `GET /api/me` 反而 **200 + 陈旧数据**（缓存只在成功路径被替换）；
3. **省略** `pronouns` 键的最小 body **同样**触发（`_me_put` 是无条件
   `body.get("pronouns")`，而文档语义是"省略 = 清空"）；
4. `pronouns: ""` 被契约 `_text()` 拒 400 ⇒ **null 是契约允许的唯一"清空"信号**；
5. 污染后按"最后已知 revision"重试 → **409 且 `currentRevision` 谎报**（读的是陈旧
   进程内缓存：报 1，库实为 2），文档承诺的 CAS 恢复路径**死循环**；
6. `health_check()` 返回 **True** 而 `is_available` 为 **False** ⇒ `/ready` 的
   identity 门禁**保持绿**（探的是 ping，不是装载结果）。

**根因（哪一层第一次无法表示该状态）**：**域模型缺少"该字段可空"这条不变量**。
不是读 schema 太窄、也不是 mapper 不对称：

- 写契约 `UserIdentityUpdate.pronouns: Optional[str]`（`frontend_contract/rest.py:755`）
- 读契约 `UserIdentityProfile.pronouns: Annotated[Optional[str], TsNull()]`（`rest.py:727`）
- 设计稿 §5.1 列 `string?`；§11.1 与 `electron-backend-protocol-v2.md:602` 明确
  「省略 `preferredAddress`/`pronouns` 表示清空」；`_me_put:254` 正是把省略映射成 `None`
- 域模型 `core/profile/user_identity.py:26` 却是非空 `str`
- `_from_doc`（`user_identity_repo.py:51-58`）是**忠实的** camelCase↔snake_case 映射，
  它正确地把 `null` 交给了域模型 —— 域模型拒收
- 两侧写路径都不校验：`_normalize_updates` 只过滤**字段名**；repo 直接拼 `$set`；
  `_update_local` 用 `setattr`（**绕过 pydantic**，本地模式静默接受 `None`）

即：**不变量只写在注解里，且只在读侧被强制**。

**相邻字段**：`preferredAddress` / `defaultCharacterId` 域模型本就是 `str | None`，
null 端到端正常 ⇒ 根因**特定于 `pronouns`**，不是通用 mapper 问题。

**classification**：`CONFIRMED_USER_REACHABLE` / **CRITICAL**。

### B3-CB-2 — `EXPECTED_INDEX_OPTIONS` 键名错误 → **FIXED**

**入口**：**startup** —— `check_schema_drift` 是真实启动步骤
（`_STARTUP_STEPS` → `_lifecycle_persistence.py`）。

**差分证据**（同一 backend、只改键名）：

```text
A) 构造「idempotency.expires_at_1 在库里没有 TTL」：
     generations  → option_conflicts 命中
     idempotency  → **不命中**（门禁死）
B) 仅在内存里把键改成 'idempotency'（其余一字不动）：
     idempotency  → 立刻命中 ('expires_at_1',)
```

**危害比"少报一条"更重**：`_option_mismatches` 用 `expected.get(collection, {})`，
键不存在即**该集合一个选项都不比**；而它的索引名照样在 `EXPECTED_INDEXES` 里被扫描
—— 退化成**"扫了、没比、报健康"**。库里 `expires_at_1` 若丢了 TTL，记录会**永不回收**，
自检不但不报错，连那条 ERROR 级的解释与处置指引都不会打印。

已确认该集合确实会被扫到：`idempotency_repo.connect()` 对注入 db **不 early-return**，
`expires_at_1` 真被建成 TTL 索引。

**原报告的"该表无 AST 守卫"子断言：成立，且比报告更强**——把整张
`EXPECTED_INDEX_OPTIONS` 换成垃圾，守卫**仍全绿**（该表的 AST 覆盖为 0）。
即文件 docstring 自称的"由 AST 反向校验守护…故不会静默过期"是**失实**的。

**classification**：`CONFIRMED_DEPLOYMENT_REACHABLE` / **MEDIUM**
（门禁缺陷，非产品缺陷——但它正是"假保障"那一类）。

## 5. `pronouns = null` 全链路分析

### 5.1 write → store → read → serialize

| 环节 | 位置 | 对 `null` 的态度（修前） |
|---|---|---|
| request schema | `frontend_contract/rest.py:755` `UserIdentityUpdate.pronouns: Optional[str]` | **允许**（且 `_text()` 拒 `""`，故 null 是唯一清空信号） |
| 路由 | `core/input/character_routes.py:254` `body.get("pronouns")` | 省略 → `None`（**无条件**映射） |
| validation | `profile_store._normalize_updates` | 只过滤**字段名**，不看值 → `None` 通过 |
| persistence | `user_identity_repo.update_if_revision` → `$set {pronouns: None}` | **Mongo 正常存 null**（真实库实测已提交） |
| read model | `user_identity_repo._from_doc` → `UserIdentity.model_validate` | **抛 ValidationError** ← **第一层失败点** |
| serialization | `UserIdentityProfile(**profile.model_dump())` | 契约本就是 `string \| null`，**本来就能序列化**（`TsNull`） |

### 5.2 六个必答问题

1. **`null` 是否被 API schema 明确允许？** **是**。写侧 `Optional[str]`；读侧
   `Optional[str] + TsNull()`（生成的 TS 就是 `pronouns: string | null`）。
2. **domain 是否也认为合法？** 修前**不合法**（非空 `str`）——这就是不对称所在；
   修后合法。
3. **Mongo 能否保存？** **能**，且**真的保存了**（真实 MongoDB 8 实测：
   `pronouns=None, revision=2, initialized=true`）。
4. **哪一层第一次无法处理？** **`_from_doc` 的 `model_validate`**（域模型层），
   不是存储层、不是契约层。
5. **是 write schema 太宽 / read schema 太窄 / mapper 不对称 / 缺 domain invariant？**
   —— **缺 domain invariant**。写 schema 的宽松是**刻意的**（清空语义需要它）；
   读 schema **比域模型更宽**（它早就承诺 `string | null`）；mapper 是忠实映射。
   一句话：**不变量只写在注解里，且只在读侧被强制**。
6. **产品语义上 `pronouns = null` 表示什么？** **"已清空 / 未设置"**，
   存储为 `null`，下游解析为全局默认「她」。依据（既有权威，非本批发明）：
   设计稿 §5.1 字段表 `string?`；设计稿 §11.1 与
   `docs/electron-backend-protocol-v2.md:602` 的「省略 = 显式清空」；
   冻结契约模型本身；前端 `contract.generated.ts` 的 `string | null`。

### 5.3 为什么修 read 侧而不是 write 时拒绝

§15 的判据是"null 是否合法产品状态"。**是**（清空是文档化的用户操作），
故按原则**让 read path 正确支持**，而不是 write-time reject ——
后者会把文档化的"清空"流程变成 400。

同时**没有**选"写时把 null 改写成「她」"：那会让 GET 上"已清空"与"用户就填了她"
**无法区分**，是语义损失（属产品决策，不做）。

### 5.4 缺字段 ≠ 显式 null（修法的关键约束）

| 文档形态 | 修前 | 修后 |
|---|---|---|
| 键**完全缺失**（legacy） | `"她"`（pydantic 默认值） | **`"她"`（不变）** |
| 键存在且为 `null` | **ValidationError** | **`None`** |
| 键存在为正常值 | 该值 | 该值 |

修法**保留默认值** `= LOCAL_DEFAULT_PRONOMS`，正是为了守住第一行：
若写成 `str | None = None`，所有**存量记录**（键缺失）会突然在 API 上变成"已清空"
—— 那是本修复最容易引入的反向回归，已用
`test_missing_pronouns_key_in_legacy_doc_keeps_bootstrap_default` 钉住。

### 5.5 为什么不是"在 GET 里吞异常"

被明确禁止的伪修（`try/except: pronouns = ""`）**没有**采用。本修法改的是
**真正的 schema/mapper/domain 对称性**：一行类型注解，让域模型与冻结契约一致。
没有新增 try/except，没有静默默认替换。

## 6. Preflight Analysis — Authority vs Runtime

### 6.1 Authority Matrix（修前）

| Concern | Preflight reads | Runtime reads | Same authority? | Consequence when they disagree |
|---|---|---|---|---|
| LLM API key | `os.getenv(env_key)` | `resolve_api_key`（env 为主） | **✅** | — |
| LLM base URL | `os.getenv(url_key)` **only** | `resolve_base_url`：explicit > env > `providers.yaml::<p>.base_url` | **❌** | `providers.yaml` 有默认值时误报 FAIL |
| Mongo URI | `os.getenv("MONGODB_URI")` **only** | `config.database.mongodb_uri`（`ConfigLoader`: CLI>env>YAML>默认） | **❌** | `config.yaml` 有地址时误报 FAIL |
| Milvus URI | `os.getenv("MILVUS_URI")` **only** | `config.database.milvus_uri`（同上） | **❌** | 同上 |
| TTS 地址/凭据 | `os.getenv(key)` **only** | `resolve_base_url` / `resolve_api_key` | **❌** | `gpt-sovits` 地址只在 yaml（`env_key: ""`）→ 误报"将不可用" |
| STT 地址/凭据 | `os.getenv(key)` **only** | 同上 | **❌** | `sensevoice` 无默认地址 → 告警（此处恰好正确） |
| 嵌入模型缓存 | `find_local_model()`（与加载器**同一实现**） | 同一个 | ✅ | —（这是 Batch 之前刚修好的先例，判据已对齐） |

**核心语义漂移**：预检在问「**env 变量是否被设置**」，而运行期在问
「**这个关注点最终解析出了什么**」。前者是配置的**外观**，后者才是**启动条件**。

### 6.2 修法（判据改为"运行期能否满足启动条件"）

- 新增 `_resolved_llm_url()` / `_provider_url_note()`：**调用运行期同一个
  `resolve_base_url`**，预检不再自己实现一套解析（消除"两处真相"）。
  只有**任何一层都没有地址**才 FAIL（LLM/TTS/STT 的 WARN）。
- `_check_mongo_env(config)` / `_check_milvus_env(config)`：读
  `config.database.*`（运行期真正会用的值），删掉"必须设 env"这条假前提。
  **按 owner 裁定保持静态判据**，不引入连通性探测（`--full` 才探活）。
- `--full` 的 `_check_milvus_connectivity` / `_check_mongodb_connectivity`：
  同样改读 `config.database.*`，否则 config.yaml 配了地址时会去连**空串**。
- **未改**任何 env 变量名与优先级：`CLI > env > YAML > 默认` 原样保持，
  没有重新引入"bootstrap truth 当 runtime truth"。

### 6.3 防"反向假绿"（实测）

真非法的配置**继续被拒**：

```text
mimo/mimo-v2.5 在 providers.yaml 里 base_url 是空串（云端端点须由部署方提供），
只设 MIMO_API_KEY 时：
  [FAIL] LLM provider 'mimo' 没有可用的 base URL — 请设置 MIMO_URL，…   → 退 1
运行期 LLMFactory.create 同样拒绝建连（registry 的 `if not base_url: raise`）。
```

判据是「**有没有地址**」，不是「**是不是内置 provider**」——
另一个变体（把 deepseek 的 yaml 默认地址清空）同样 FAIL，已入测试。

### 6.4 Optional Subsystem Containment（与 Batch 1 不变量对齐）

TTS/STT 缺失**只 WARN**，`_COUNTS.failed` 保持 0 ⇒ 主进程不因可选子系统被拒。
这与 Batch 1 已建立的「optional subsystem failure 不应让整个 Agent startup rollback」
一致；C4 用例专门钉住这一点。
