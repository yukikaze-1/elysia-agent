## 3. BE-S4-INT-P0-01：内置 SenseVoice Profile 测试必须继承默认地址

### 3.1 真实现象

环境未显式配置 `SENSEVOICE_URL`，本机 SenseVoice 正常监听默认端口时，调用：

```http
POST /api/providers/test
Content-Type: application/json

{
  "service": "stt",
  "provider": "sensevoice",
  "model": "sense-voice"
}
```

当前返回的业务结果为：

```json
{
  "ok": false,
  "latency_ms": 0,
  "error": "Request URL is missing an 'http://' or 'https://' protocol."
}
```

这不是一个合理的“服务离线”结果；请求甚至没有使用项目公开的默认地址 `http://localhost:20042`。

### 3.2 根因

当前存在两条配置路径，默认值没有保持一致：

1. 正常 Agent 启动通过 `STTFactory.from_config()` 创建 STT，`Module/stt/config.py::STTConfig` 提供默认值 `http://localhost:20042`；
2. `/api/providers/test` 在 `core/input/provider_routes.py::providers_test_handler()` 中直接调用 `STTFactory.create()`；
3. 内置 provider 没有请求体 `base_url` 时，handler 不会注入地址；
4. `Module/stt/registry.py::STTFactory.create()` 再从 `Module/config/providers.yaml` 解析默认值，而 `stt.sensevoice.base_url` 当前是空字符串；
5. 工厂最终显式传入 `base_url=""`，覆盖 `SenseVoiceBackend` 构造函数自身的 `http://localhost:20042` 默认值。

关键位置：

- `core/input/provider_routes.py:212-319`
- `Module/stt/registry.py:18-72`
- `Module/config/providers.yaml:70-76`
- `Module/stt/config.py:9-25`
- `Module/stt/sensevoice.py:66-91`

### 3.3 必须修改的行为

1. 内置 `sensevoice/sense-voice` 在请求体没有 `base_url` 且环境没有 `SENSEVOICE_URL` 时，必须稳定解析为 `http://localhost:20042`；
2. 非空请求体覆盖、环境变量覆盖和配置默认值的优先级必须只有一处权威实现，Profile 测试与正常 Agent 启动不得走出不同结果；
3. 不要把“要求每台机器都在 `.env` 重复填写默认地址”作为修复；项目既然公开了内置默认值，就应在代码路径中兑现；
4. 自定义 STT 仍必须显式提供合法 `base_url`，不能因内置默认值修复而放宽；
5. 保留现有 SSRF/runtime 守卫。默认 loopback 是项目受控的本地内置 provider，用户提供的覆盖地址仍按现有安全策略校验；
6. Profile 测试失败时继续返回结构化 `ProviderTestResult`，不得泄露密钥、内部路径或完整敏感请求。

实现方式可以选择在 provider 默认配置、统一解析器或工厂层修复，但最终只能有一套可测试的优先级语义，不能再依赖构造函数默认参数碰巧兜底。

### 3.4 必须补充的测试

- 未设置 `SENSEVOICE_URL`、请求体也无 `base_url`：工厂和 `/api/providers/test` 均使用 `http://localhost:20042`；
- 设置 `SENSEVOICE_URL`：环境覆盖默认值；
- 请求体提供允许的 `base_url`：按既有优先级覆盖；
- 使用本地 stub 的正式 `/api/providers/test`：返回 `ok=true` 和非负 `latency_ms`；
- 服务未启动：返回可诊断的 `ok=false`，不能再报“URL 缺少协议”；
- 地址格式错误或被 SSRF 策略拒绝：返回既有结构化失败，不绕过安全检查；
- custom STT 缺少地址：仍明确失败；
- LLM/TTS 的既有 Profile 测试行为不得回归。

### 3.5 完成验收

在不新增 `SENSEVOICE_URL` 的干净本地配置上启动默认 SenseVoice，然后从正式 `/api/providers/test` 测试 `sensevoice/sense-voice`，必须得到真实连通结果；停止服务后同一请求应得到服务不可达类结果，而不是 URL 构造错误。

## 5. BE-S4-INT-P1-01：提供确定性的阶段 4 smoke/runbook

### 5.1 目标

新增一个后端可维护的 smoke 脚本或明确 runbook，用来在真实 Electron 联调前快速证明阶段 4 的关键语义。默认路径使用本地 stub/固定 fixture，真实付费 provider 只作为显式 opt-in，不得让 CI 依赖外部额度、网络或人工凭据。

仓库已有可复用音频 fixture：

- `core/input/tests/fixtures/sample_16k_mono.pcm`
- `Module/stt/tests/fixtures/sample.wav`

### 5.2 最小场景

#### Profile 与模型切换

- 列出 LLM/STT/TTS provider，响应不回显 API key；
- 测试成功、服务离线和非法配置；
- 保存/删除自定义 Profile，验证正在使用的 Profile 不可删除；
- 切换模型成功后只影响新请求；
- 切换失败时保留原活动模型，不能留下半切换状态。

#### 普通录音

- start → 发送 16kHz mono s16le PCM → stop；
- stop 后只产生 `voice.transcript` 待确认字幕，不自动发送聊天消息；
- commit 才创建用户消息并触发 generation；
- discard 不创建消息、不触发 generation；
- 取消、空录音和 STT 失败均可清理状态并再次录音。

#### 实时语音

- `voice_session.started → partial → turn → ack → ended` 顺序和关联 ID 正确；
- 每个 turn 自动创建且只创建一次用户消息；
- 背压、取消、异常结束后不会把上一会话残留到下一会话；
- generation/TTS 音频与所属 turn、conversation 保持一致。

#### 听写

- partial 只用于界面预览；
- final 只返回文本，不写聊天消息、不写会话历史、不触发 Agent generation；
- cancel 返回 `dictation.cancelled` 并清理缓存；
- 同一个 `clientRequestId` 的结束与取消不会重复 settle。

#### TTS 与播放控制

- voices 列表和当前 voice 可读取；
- preview 成功、provider 离线和 voice 非法均有确定响应；
- `audio_start → audio* → audio_end` 的 stream/seq 连续；
- `audio.cancel` 后返回 `audio_cancelled`，不再发送该 stream 的孤儿 chunk；
- `set_tts_voice_result` 成功/失败均能关联到实际状态。

### 5.3 安全与可重复性要求

- 音频输入描述统一写清：PCM 16kHz、mono、signed 16-bit little-endian；
- 固定 fixture、端口和 stub 响应，避免依赖麦克风、扬声器及随机文本；
- 不记录密钥、完整音频 payload、真实转写正文或带签名的完整 URL；
- 每次运行记录后端 SHA、protocol version、场景结果和首个失败点；
- smoke 失败必须返回非零状态，不能只打印错误后继续显示“通过”。

### 5.4 完成验收

一条文档化命令可在无付费外部服务的环境重复运行最小 smoke，并明确区分“确定性契约 smoke 通过”和“真实 provider/Electron 联调通过”。
