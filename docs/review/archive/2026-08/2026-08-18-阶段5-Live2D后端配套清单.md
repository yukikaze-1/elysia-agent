**日期：** 2026-08-18（Asia/Shanghai）

**结论：** 阶段 5 P0 是前端本地渲染能力，**后端无阻塞性代码缺口**。本清单把“必须补的文档口径”和“可选的指令帧扩展”分开：B-1 是联调前必须补；B-2 是 P1 可选项，第一轮真实联调不要求实现；B-3 是联调环境动作。

## 1. B-1【P0·文档必须补】`generation.completed.mood` 语义口径

### 1.1 问题

后端 `generation.completed.mood` 实际是 LLM `<mood>` 标签的自由文本（常见值：`开心`、`平静`、`难过`、`惊讶` 等），不是英文枚举。前端阶段 5 按本地映射表消费该字段；联调复核发现前端目前只认英文码，已列入前端整改清单。

为避免未来后端或契约层误把 `mood` 收敛成英文枚举、再次造成跨仓漂移，后端文档必须冻结以下口径：

### 1.2 需修改的文档

- `docs/electron-backend-protocol-v2.md`
  - §1/§2 的 `generation.completed` 字段说明补一句：`mood` 为自由文本/中文标签，**非枚举**；客户端负责本地归一映射，未知值安全忽略。
  - §7（v2 通道）同样补一句，避免“expression 抑制、mood 落位”被理解成 mood 有固定值域。
- `frontend_contract/ws_message.py`
  - `GenerationCompletedMessage.mood` 的 description 改为：“心情自由文本（如 `开心`/`平静`），非枚举；前端本地归一，未知值忽略”。
  - 重新生成 `contract.generated.ts` / `contract.schema.json` / `contract.raw.ts`（description 变化会影响生成产物，跑 `make gen-types` + `make check-types`）。

### 1.3 验收

- 协议文档和契约生成产物明确 mood 为自由文本；
- 不新增枚举、不改变 wire 字段类型；
- `make check-types` 全绿。

## 2. B-2【P1·可选扩展】`live2d.directive` 后端指令帧

### 2.1 现状

前端阶段 5 批次 C 已冻结 `live2d.directive` 的**前端契约超集**：

```json
{
  "type": "live2d.directive",
  "expression?": "string",
  "motion?": "string",
  "state?": "idle|listening|thinking|speaking|happy|sad|surprised",
  "priority?": 0-3,
  "durationMs?": 0-30000
}
```

当前后端：

- `frontend_contract/ws_message.py` 无该模型；
- 后端不发送该帧；
- 前端联调清单已把 C3-3 定为**条件项**：后端不实发时，验证前端防御路径 + 真实 emotion 路径即可。

### 2.2 决策

**第一轮阶段 5 真实联调：不实现 B-2。** 理由：

1. 阶段 5 设计把后端指令标为“可选、低优先级建议”，不是 P0；
2. `expression`/`motion` 必须匹配前端已安装模型的白名单，后端没有模型清单，发具体文件名没有可靠来源；
3. 情绪建议已有 `generation.completed.mood` + 建连 `expression` 两条真实数据路径，前端本地映射即可覆盖联调目标；
4. 提前实现会产生无消费者验证的协议面。

后续若有明确产品场景（例如后端下发“waiting_permission/working”或指定动作），再按下列规格实现。

### 2.3 若后续实现，需要做的后端改动

1. **契约层**
   - `frontend_contract/ws_message.py`：
     - 新增 `DirectiveState` StrEnum（七值，与前端冻结一致）；
     - 新增 `Live2DDirectiveMessage(ContractModel)`，扁平字段 `expression? / motion? / state? / priority? / durationMs?`；
     - 加入 `ServerMessage` 判别联合；
   - 重跑 `make gen-types` / `make check-types`，更新 TS/JSON Schema/raw TS；
   - 若纳入 golden frames，更新 `scripts/gen_contract_frames.py` 与 `docs/archive/frontend-handoff-v2/traces/`，并保证 `--check` 零 churn。
2. **发送通道**
   - `Module/output/protocol.py` 增加 `on_live2d_directive(...)` 能力；
   - `Module/output/manager.py` 增加按 capability 路由的 broadcast 方法；
   - `Module/output/websocket.py` 用 `Live2DDirectiveMessage.wire_dict()` 发送；
   - 仅向 v2 通道发送；v1 保持现有 `expression`/`action` 行为不变。
3. **生产者（需要先有明确产品口径，不要拍脑袋）**
   - 候选来源：CharacterEngine 心情变化、工具审批状态、TTS 开始/结束、IdleMonitor 主动事件；
   - 必须定义：何时发、state 取值、expression/motion 是否留空、priority/durationMs 默认值；
   - `expression`/`motion` 只允许通用稳定名（或由前端模型白名单决定是否忽略），后端不得传路径/URL。
4. **测试**
   - 契约模型 wire 测试；
   - OutputManager 版本分流测试（v1 不发、v2 发）；
   - WS 路由级测试：合法帧、越界 state、durationMs 超限、未知字段；
   - `make test-quick` / `make lint` / `make pyright` / `make check-types` 全绿。
