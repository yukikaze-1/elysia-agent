## 4. `pinned` / `follow_latest` 与 generation 身份

严格使用正式命令 `STAGE_H_FIXTURES=1 ... scripts/dev/seed_stage_h_pinned.py` 创建新数据夹具：

1. fixture 角色、pinned/follow_latest 两个实例和会话能通过真实 Electron/REST 读取；
2. Definition 经公开 API 从 revision 1 推进到 revision 2；
3. pinned 下一轮 generation 继续绑定 revision 1；
4. follow_latest 下一轮 generation 绑定 revision 2；
5. 两轮的 `characterId + characterInstanceId + characterRevision` 与各自会话 binding 一致；
6. terminal 帧缺少 `conversationId` 时，前端仍按 started 时冻结的 `generationId` 归属正确收口。

该场景无数据库手工修补，关闭 H-44 与 BE-H2-01/02 的最终门禁。

## 5. A/B tail 强串行与隔离

最终真机场景与 §9.5 冻结口径一致：

1. A 收到 `generation.completed` 后立即激活 B；
2. A 的 tail lease 未释放时返回 retryable `AGENT_BUSY`，活动会话仍为 A；
3. busy 窗口被连续观测，前端未乐观切换；
4. tail 释放后重试成功激活 B；
5. B generation 完成，A/B 使用不同 instance 且身份 tuple 正确；
6. 后端只读审计确认 B 当前 buffer 不含 A 唯一标记，B 最新 Prompt 不含 A 标记且包含 B 自身标记。

因此公共 API 强串行语义和 P0-R1 的纵深隔离同时得到真实证据。`generation.completed` 仍只表示可见生成终态，不承诺后台收尾已经完成。
