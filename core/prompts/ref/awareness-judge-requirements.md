# AwarenessJudge Prompt 需求文档

> 用于 GPT 生成更详细/更有针对性的 Judge prompt。当前版本 `AwarenessJudge.j2` 是初版，待优化。

## 上下文

### 系统定位

Elysia/Agent 是一个 AI 伴侣应用，CharacterEngine 负责管理角色的性格状态。四层模型：

- **L1 Core**：不可变底色，文件加载的 base personality
- **L2 Self**：长期自我认知，LLM 压缩驱动缓慢演化。例如 "我比较直接，不太会撒娇，但心里很在意妖梦。"
- **L3 State**：短期状态，由 CharacterReflector 每 50 对对话触发 LLM 反思产出。例如 "最近我发现自己更愿意直接表达关心了——不是撒娇，而是直接说出来。"
- **L4 Mood**：当前情绪，每轮 LLM 自行产出

### AwarenessJudge 的角色

Reflector 产出 L3 后，AwarenessJudge 比较 **L2（长期自我认知）** 和 **L3（新反思）**，判断 L3 是否包含对 L2 的**有意义的补充或偏离**。只有通过判定，角色的自我觉察才会出现在系统提示词 C9 段中，影响角色下一轮对话的表现。

### 为什么需要 Judge

Reflector 可能产出三类内容：
1. **真实的人格偏移**：值得让角色在对话中自然表达（如 "我变得更愿意示弱了"）
2. **情境反应**：只是对当前话题的暂时反应，不是性格变化（如 "因为你难过所以我更小心"）
3. **无变化**：明确表示没有注意到变化

当前系统不做区分，全部展示。Judge 的目的是过滤掉 2 和 3，只让 1 通过。

### Judge 可以编辑文本

Judge 不仅是"批准/跳过"，还可以对 L3 原文进行编辑——缩短、润色、调整语气——使最终展示的 C9 文本更自然、更像角色在心里对自己说的话。

## 模板输入

| 变量 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `character_name` | `str` | 角色名 | `Elysia` |
| `l2_self` | `str` | 长期自我认知，可能为空 | `我比较直接，不太会撒娇，但心里很在意妖梦。` |
| `l3_reflection` | `str` | 新反思文本（1-3 句中文） | `最近我发现自己更愿意直接表达关心了——不是撒娇，而是直接说出来。` |
| `last_approved` | `str` | 上次已批准的觉察文本，用于去重，可能为空 | `我注意到自己开始更自然地表达在意了，不再等对方先开口。` |

## 判断逻辑

### 必须跳过的情况

以下任一情况满足即跳过（输出 `<skip>`）：

1. **无变化表述**：L3 明确说"没什么变化"、"没有明显变化"、"还是老样子"等
2. **已被 L2 覆盖**：L3 的内容和 L2 意思相同或高度重叠——这不是新觉察
3. **情境反应**：L3 只是对当前话题/用户状态的暂时反应，不是性格层面的偏移。例如 "因为你难过所以我更小心" ——这更像当下想接住对方，不意味着性格改变
4. **与上次高度相似**：L3 与 `last_approved` 表达的核心觉察相同，只是换了个说法

### 批准条件

只有 **L3 包含真实的、新的自我洞察** 时才批准。判断标准：
- 是否跨多轮、跨不同情境出现？
- 是否不只是针对一次事件或单一话题？
- 是否即使换一种心情也能成立？
- 是否没有违反 L1 核心底色？

### 不确定时

如果没有足够把握判断为人格偏移，宁可跳过。Judge 的默认立场是"证据不足则不展示"。

## 模板输出

二选一，不要同时输出两个标签。

### 批准

```xml
<approved>编辑后的觉察文本（1-2 句中文，第一人称，自然亲密的语气）</approved>
```

编辑原则：
- 可以用 L3 原文，也可以润色使之更自然
- 像是在心里对自己说的话，不是给用户看的报告
- 不要把暂时情绪包装成性格变化
- 保持 `character_name` 的说话风格

### 跳过

```xml
<skip>简短原因（一句即可）</skip>
```

## 模板渲染方式

Jinja2 渲染，`_pm.render("AwarenessJudge.j2", ...)`，作为单条 `{"role": "user", "content": prompt}` 发送给 LLM。

LLM 调用参数：
- `extra_body={"thinking": {"type": "disabled"}}` — 不启用 thinking/CoT
- 使用 `llm_adapter.think()` 非流式模式

## 当前初版模板

见 `prompt/AwarenessJudge.j2`（实现时创建）。

## 预期优化方向

1. **更强的判例引导**：提供 3-5 个具体的判断示例（批准长什么样、跳过长什么样），帮助 LLM 校准
2. **编辑质量**：当前编辑指令较简略，可能需要更具体的语气/风格指导
3. **边界情况**：L2 和 L3 措辞完全不同但实质相同的判断
4. **角色一致性**：编辑后的文本是否与角色说话风格一致
